# 02 · 关键决策与踩坑

## 决策

**1. 选「判定成色」这条路线，不选经营流。**
任务书给了四条参考路线。经营流（定价、采购、升级）要做的界面比三小时能画完的多，爽快打击型只要一种输入，规则还能写成纯函数被测。所以内核定成：三次出手，成色决定钱和口碑。

**2. 判定写进 `src/core/`，场景只负责画。**
`judge()`、`qualityOf()`、`gradeOf()`、`coinsFor()`、`reputationDelta()` 全是纯函数，测试里可以「让机器人打一千局」而不用开浏览器。场景只做三件事：算指针在哪、把结果画出来、把状态交给 core。

**3. 三个阶段，一种输入。**
火候 / 锻打 / 淬火都按空格，但速度一个比一个快、窗口一个比一个窄（0.85 → 1.05 → 1.55 次往返/秒）。玩家学一次就会，难度靠数值递进，不靠加按键。

**4. 判定窗口按「指针穿过绿区要多久」倒推。**
指针是三角波，一个来回 `1/speed` 秒走 2 个单位，所以穿过 ±w 需要 `2w/speed` 秒。第一天三锤取 w=0.2、speed=1.05，约 380 毫秒的命中区，完美区约 190 毫秒——比音游宽松，因为这里的重点是「看准了再落手」，不是背节奏。

**5. 声音全部代码合成。**
素材包里没有任何音频文件（`manifest.json` 里登记了 10 个 ogg/mp3，文件都没提供）。与其让游戏静音，不如用 WebAudio 现场合成：音效沿用模板的 `synth.ts` 配方，背景音乐新写了 `src/audio/bgm.ts`（五声音阶、8 小节循环）。同时也留了「有真文件就放文件」的分支。

**6. 不改框架文件。**
`src/engine/`、`src/main.ts`、`tools/` 一行没动。自己加的走查脚本放在 `verify/`，背景音乐放在 `src/audio/`，都不影响模板原有的命令。

## 踩坑

**① `npm run check` 在沙箱里跑不起来**
vitest 默认用 fork 池，`spawn` 被运行环境拒绝（EPERM）。把 `vite.config.ts` 的 `test.pool` 设成 `threads` 就好了：规则测试都是纯逻辑，线程池更快也不依赖子进程。

**② 截图自检起不来浏览器**
`npm run shot` 用 playwright 直接拉 Chrome，同样被拦。改成先手动起一个带 `--remote-debugging-port=9222` 的 Chrome，再用 `connectOverCDP` 连上去（就是 `verify/tour.mjs`）。这条路径也顺带解决了「截图脚本只会按空格、按不出好成色」的问题：走查脚本每帧读 `ctx.debug()` 的指针位置，靠近中心才出手。

**③ 按一下空格连跳两步**
模板里 `listenKeys` 已经把这个问题处理掉了（监听 window 而不是 Phaser 的键盘队列）。但走查脚本自己踩了一次：在接单页按空格进打造页之后，脚本又按了一下，正好把新手提示弹层关掉了，于是第一次跑没截到提示。修法是「按完等场景真的换了再继续」。

**④ 四处布局问题（走查截图看出来的）**
- 接单页：气泡压住订单卡、`要求成色` 和徽章名字重叠 → 重排卡片，徽章和文字并排。
- 打造页：阶段文字压在铁砧上 → 把铁砧缩小上移，文字挪到砧子下方。
- 打造页：锤子悬在半空，没砸在铁坯上 → 位置和角度重摆，落锤时同时下移。
- 淬火：背景里本来就有一只水桶，我又放了一只，成了两只 → 水桶挪到铁砧右侧，并让铁坯真的「进桶」。

**⑤ 新手提示的正文跑到标题上面**
`addText` 在不传 `wrap` 时是居中锚点，多行文字会上下对称展开，正好压住标题。传了 `wrap` 才是左上锚点。这是模板里一个容易忽略的细节，记在这里。
